<objective>
Cover the price-history backend's edges and serialization contract with real
tests against a real MongoDB, and record in code the two decisions this phase
resolved by discretion: that an unknown product id yields `200 []` rather than a
404, and that the full unbounded series is served deliberately at this data
volume.

Purpose: the tracer proved the happy path. Everything that goes wrong here is
silent — an RFC-822 timestamp that renders as an invalid date, a leaked ObjectId
that 500s, a lost sort that draws a scribble instead of a line, a 404 for a
brand-new product. Each of those needs its own assertion.

Output: `get_price_history` unit cases in `tests/test_price_service.py`,
history-route cases in `tests/test_api_products.py`, and two docstring decisions
recorded in the service and the route.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Flask API | `GET /products/<product_id>/history` accepts an untrusted URL path segment, including ids absent from the catalog |
| Flask API → MongoDB | `product_id` crosses into the `price_points` query filter |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-02 | Tampering | `product_id` path segment → `db.price_points.find` filter | low | mitigate | Task 1's `test_price_history_scoped_to_one_product` proves the filter is an exact equality match that returns only the requested product's documents, so a crafted id cannot widen the result set; the value is never interpolated into a query operator (ASVS V5) |
| T-08-01 | Information Disclosure | history response element shape | low | mitigate | Task 1's `test_price_history_element_shape` asserts the key set is exactly `{ts, total_price}`, proving neither the internal BSON `_id` nor unrequested fields leak to an unauthenticated caller, and that no unhandled serialization `TypeError` can reach the client |
| T-08-05 | Information Disclosure | unknown-id probing via `GET /products/<id>/history` | low | accept | The catalog is entirely public and the detail route already discloses membership via its 404; returning `200 []` for both an unknown id and an empty catalogued product discloses strictly less than the existing detail route, so no new disclosure surface is created |
| T-08-03 | Denial of Service | unbounded response size | low | accept | Task 3 records the volume assumption and its revisit trigger in the service docstring; REQUIREMENTS.md documents roughly 6 points per day per product, well below any practical response-size concern for v1.1 |
</threat_model>
