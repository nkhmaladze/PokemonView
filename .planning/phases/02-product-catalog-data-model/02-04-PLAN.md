<objective>
Create the shared MongoDB data model this and all later phases depend on: the `products` catalog collection (with a `$jsonSchema` validator and the compound index the phase's query requirement needs) and the `price_points` time-series collection reserved — created empty now — for Phase 3's ingestion worker. This satisfies the "persisted in MongoDB, queryable by set and product type, schema reserving item/total price + time-series fields" success criterion (CATALOG-02, ROADMAP §Phase 2 SC-3).

Purpose: Time-series collection options (timeField/metaField/granularity) and the $jsonSchema validator are creation-time-only — MongoDB has no supported path to retrofit them onto an existing plain collection (Pitfall 1). Getting `price_points` right now, empty, avoids a forced drop-and-recreate migration in Phase 3. The validator is this phase's V5 input-validation security control, enforced against every future writer, not just this phase's seed script.
Output: `db/init_collections.py` (the `init_collections` function) and `db/__init__.py`.
</objective>

    2. After creating `products`, create its compound index by calling `db.products.create_index` with the list of tuples `("set_name", ASCENDING)` then `("product_type", ASCENDING)` (Pattern 3 — one index supports queries on set_name alone and on set_name plus product_type via the compound-index prefix rule).

If the string `price_points` is not in `db.list_collection_names()`, call `db.create_collection` for `price_points` passing keyword arg `timeseries` set to the dict with `timeField` = ts, `metaField` = product_id, `granularity` = hours. Add a docstring or comment stating the intended per-point document shape Phase 3 will write — fields ts, product_id, item_price, and total_price — so the "reserves fields for both item-only and total (item plus shipping) price points and time-series history" success criterion is explicit. Do NOT attach a strict validator to the time-series collection.

    Import only from pymongo (bring in `ASCENDING`). The `db` handle is passed in by the caller (seed script or test fixture); this module does not read MONGODB_URI or construct a MongoClient itself.
