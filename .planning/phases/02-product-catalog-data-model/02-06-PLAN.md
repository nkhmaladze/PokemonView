## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Seed script → `products` collection | The seed's own writes cross the DB-level validator; a shape bug in curated data is caught here, not silently persisted |
| `.env` MONGODB_URI → seed process | The connection string (possibly Atlas creds) is read into the process; must never be logged or committed |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | seed upsert write path | high | mitigate | All seed writes go through the `$jsonSchema` validator (Plan 04); `UpdateOne(upsert=True)` uses parameterized filter dicts (never string-concatenated queries), establishing the parameterized-write pattern Phase 5's API must follow (V5) |
| T-02-06 | Tampering (duplication/data integrity) | non-idempotent re-seed | medium | mitigate | Deterministic slug `_id` + `UpdateOne(upsert=True)` (never `insert_many`); `test_seed_idempotent` and a live double-run prove re-running produces no duplicates (Pitfall 5) |
| T-02-02 | Information Disclosure | MONGODB_URI in seed process | high | mitigate | Read MONGODB_URI only from `os.environ` after `load_dotenv()`; never print the full connection string (print only counts / db name), reusing Phase 1's secrets-hygiene pattern |
| T-02-03 | Tampering (data integrity) | Pitch Black provisional data | low | mitigate | `verified=False` flag + non-fatal stderr warning + recorded D-02 post-release re-verification follow-up prevent provisional data from silently becoming trusted |
