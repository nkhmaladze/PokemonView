## API Response Contract (locked by this plan's Wave 0 tests)

This is Claude's-discretion JSON shape (per 05-CONTEXT.md "exact JSON field names ... Claude's discretion"), chosen for clearest frontend consumption and locked here so Plans 05-04/05/06 have a fixed target.

Service function signatures (all pure, `db` first arg, mirroring scripts/matching.py):

- `price_service.get_current_price(db, product_id) -> dict | None` — latest price_points doc by `ts` desc, NO time window (D-02); `None` only if the product has zero points ever (D-01).
- `price_service.get_trend_baseline(db, product_id, current_ts, days, tolerance_days=3) -> dict | None` — closest point to `current_ts - days` within `±tolerance_days` (D-05); `None` if none in window (D-06).
- `price_service.compute_pct_change(current_total, baseline_total) -> float | None` — `(current-baseline)/baseline*100` rounded 2dp, on total_price only (D-07); `None` when baseline is 0.
- `catalog_service.list_products(db, filters) -> list[dict]` — `filters` = `{"q": str|None, "set_name": str|None, "product_type": str|None}`; in-process filtering (D-08 combinable); default sort by `SET_ORDER` then in-set (D-10); raises `ValueError` on an invalid non-None `product_type` (V5).
- `catalog_service.get_product_detail(db, product_id) -> dict | None` — assembled detail; `None` when the product `_id` does not exist (→ HTTP 404).

`GET /products` → HTTP 200, a bare JSON array; each element:

```json
{
  "id": "perfect-order_booster_box",
  "set_name": "Perfect Order",
  "product_type": "booster_box",
  "display_name": "Pokemon TCG: Mega Evolution-Perfect Order Booster Display Box (36 Packs)",
  "release_date": "2026-03-27",
  "msrp": 161.64,
  "image_url": "https://...",
  "verified": true,
  "price_status": "ok",
  "current_price": {
    "total_price": 172.5,
    "item_price": 165.0,
    "as_of": "2026-07-10T12:00:00+00:00",
    "listing_count": 8
  }
}
```

- `price_status` is `"no_data_yet"` and `current_price` is `null` when the product has zero price_points (D-01).
- `current_price.as_of` is the literal `ts` of the shown point (D-03/PRICE-02) — no separate staleness flag.
- `current_price.listing_count` is the stored sample size, or `null` for points written before Plan 05-02.
- Both `total_price` (headline) and `item_price` (secondary) always present when priced (D-04/D-12).

`GET /products/<id>` → HTTP 200 (or 404 `{"error": "not_found"}` when the id is unknown); shape = the list element above PLUS trend, and NO raw price_points series (D-11):

```json
{
  "id": "perfect-order_booster_box",
  "...": "(same catalog + current_price + price_status fields as the list element)",
  "trend_7d":  { "pct_change": 3.14,  "status": "ok" },
  "trend_30d": { "pct_change": null,  "status": "insufficient_data" }
}
```

- `trend_Nd.status` is `"ok"` with a numeric `pct_change` when a baseline is found in tolerance, else `"insufficient_data"` with `pct_change: null` (D-06). Trend is computed on `total_price` only (D-07).
- The detail response contains NO array/list of price_points (D-11) — only the single `current_price` object and the two trend objects.

`GET /products?product_type=<bad>` → HTTP 400 `{"error": "invalid_product_type"}` (V5). Valid enum values: `booster_pack`, `booster_box`, `etb`, `booster_bundle`.

An unhandled server exception → HTTP 500 `{"error": "internal_error"}` with NO stack trace / traceback text in the body (`DEBUG=False` + global error handler; T-05-02).
