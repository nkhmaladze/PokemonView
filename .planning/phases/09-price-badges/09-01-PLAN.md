<objective>
Ship the 24h change badge end-to-end as one thin production slice: a new explicit
tolerance constant in the price service, a `trend_24h` field on the detail
response in both of its branches, and a third `TrendBadge` on the product detail
page — proven by a real HTTP-level assertion and a real page render, not by
per-layer unit tests alone.

Purpose: this is the tracer for Phase 9. It touches every layer the phase will
modify (price service, detail assembly, HTTP boundary, page render) along the
single thinnest path, and it lands on the two failure modes the research flagged
as most likely — a nonsensical reused tolerance and a zero-data branch that
silently drops the new key. Both are quiet failures that produce a plausible-
looking page, so they have to be caught on the first commit rather than the
tenth.

Output: `trend_24h` flowing from `price_points` to a rendered chip, plus the
boundary and zero-data tests that pin it.
</objective>

No new trust boundary is introduced by this plan. The two boundaries already
documented in `08-SECURITY.md` cover this data flow unchanged.

| Boundary | Description |
|----------|-------------|
| browser → Flask API | `GET /products/<product_id>` accepts an untrusted URL path segment from any CORS-allowed origin; the route itself is unmodified by this phase |
| Flask API → MongoDB | `product_id` crosses into the `price_points` aggregation filter inside `get_trend_baseline` |

## STRIDE Threat Register

ASVS level 1; blocking severity `high`. Per `09-RESEARCH.md`'s Security Domain
section, V2/V3/V4/V6 do not apply (no auth, session, access-control or crypto
surface anywhere in this app) and V5 is trivially satisfied — this plan adds zero
new query params, path params or request bodies.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-01 | Tampering | `product_id` path segment → `get_trend_baseline`'s `$match` filter for the 24h call | low | mitigate | `product_id` is bound as a plain value in an equality filter, never interpolated into a query operator or a pipeline-stage string; the 24h call reuses the identical already-verified pipeline and adds no new filter construction |
| T-09-02 | Information Disclosure | the new `trend_24h` field on the public unauthenticated detail response | low | accept | Exposes one aggregate percentage derived from data already implied by the `current_price`, `trend_7d` and `trend_30d` fields on the same public response — no new disclosure category, same boundary already accepted for Phase 8 |
| T-09-05 | Tampering | the DB-sourced `pct_change` number rendered as badge text | low | mitigate | The value passes through `TrendBadge`'s `toFixed(1)` into a React text child, which escapes by default; the component contains no `dangerouslySetInnerHTML` and builds no markup from strings, and this plan does not modify it |
| T-09-SC | Tampering | package-manager installs | low | accept | This phase installs zero packages (`09-RESEARCH.md` Package Legitimacy Audit: not applicable); no plan in Phase 9 contains an `npm install` or `pip install` task, so no install-time code-execution surface is introduced and no legitimacy checkpoint is required |
