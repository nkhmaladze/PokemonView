# Milestone v1.0 Audit Report — PokemonView

**Audited:** 2026-07-15
**Scope:** Phases 1-7 (the complete active-price-only v1 product). Phase 8 (sold-price integration, contingent on Marketplace Insights API access) is explicitly out of scope for this milestone per ROADMAP.md and REQUIREMENTS.md — its 4 requirements (INGEST-04, PRICE-04/05/06) are correctly deferred, not evaluated as gaps here.
**Status: ⚠ GAPS FOUND**

## Headline Finding

PokemonView's core value promise is: *"A user can look up a specific pack/box/ETB and see whether it's priced fairly right now, backed by both live eBay asking prices and actual sold-price history — this must always be accurate and current."*

Every layer of the v1 (active-price-only) product is **built, code-complete, and correctly wired** — the cross-phase integration check found no code-level defects in the full chain from catalog seed through the deployed React frontend. Phases 2, 4, 5, and 6 are independently verified passed with live evidence (real MongoDB queries, live test re-runs, a production `curl` against the deployed API/SPA).

However, **the pipeline has never been proven to work against real eBay data**, and the production deployment is currently serving no real prices:

- **Phase 1** (the feasibility gate meant to prove OAuth + Browse API access works, "before any layer is built on top of it") never finished — its live-verification plan (01-04-PLAN.md) was never executed, and the phase has no VERIFICATION.md at all.
- **Phase 3**'s own verification explicitly scored the live ingestion pull (INGEST-01) as unverified and routed it to human sign-off, which has sat pending since 2026-07-14 and was never resolved.
- **Phase 7**'s own verification confirms the live production API today returns `price_status: "no_data_yet"` for every product, and its Nyquist validation table independently records a production `ingestion_runs` document with `status="failed"`.
- Root cause, consistently corroborated across Phases 1, 3, and 7: `EBAY_CLIENT_ID`/`EBAY_CLIENT_SECRET` were lost in a prior `.env` incident (documented in STATE.md) and have never been replaced.
- Separately, the Marketplace Insights Growth Check — which PROJECT.md recommended submitting "as early as possible" — appears to have never actually been submitted; its tracking table is still blank template placeholders.

**In short: this is a credentials/external-dependency gap, not an architecture or code defect.** The fix is operational (obtain real eBay Production credentials and run the worker once), not a rebuild.

## Recommendation

This is not a "go build more features" gap — it's a "close the loop on what's already built" gap. The fastest path to a fully-proven v1.0:

1. Restore `EBAY_CLIENT_ID`/`EBAY_CLIENT_SECRET` (or obtain them for the first time if the original values are unrecoverable).
2. Run Phase 1's deferred live verification (01-04-PLAN.md) to prove OAuth + Browse API access and capture the 50-100 real fixtures the phase was always supposed to produce.
3. Resolve Phase 3's pending UAT (03-UAT.md) by running `python -m scripts.ingest_worker --once` against real eBay Production and confirming a real `active_listings`/`ingestion_runs` document.
4. Let the already-deployed, always-on Fly worker pick up the next scheduled run — no redeploy needed (per Phase 7's D-05/D-06 decision).
5. Separately: actually submit the Marketplace Insights Growth Check (still not done) so Phase 8's contingency clock starts.

None of this requires new code — Phases 1-7's architecture is sound and cross-phase-verified.
