# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — plain CSS (CSS Modules colocated with components, per `frontend/src/components/*.jsx` + `*.module.css`) |
| Icon library | none — inline SVG only where a glyph is unavoidable (thumbnail placeholder, back-arrow); trend direction is communicated via color + sign, not icon glyphs |
| Font | system UI stack: `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif`. Apply `font-variant-numeric: tabular-nums` to every price and percentage value so digits align in columns in the dense list. |

**Rationale for "none":** `06-RESEARCH.md`'s Standard Stack section enumerates every dependency this phase needs (`react`, `react-dom`, `vite`, `react-router`, Vitest tooling) and deliberately excludes any CSS/component framework, icon library, or `axios` — the project's established pattern (Flask over Django, no Celery, no `axios`, no `recharts` until Phase 8) is minimal-dependency by design. Introducing shadcn/Tailwind here would be an unvetted architectural addition not backed by any upstream decision. A 2-route, ≤16-item dense list does not need a component library to hit this spec's bar — it needs consistent tokens, which this file provides.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, badge internal padding, tabular-num digit gaps |
| sm | 8px | Gap between price headline and secondary item-price line, chip internal padding |
| md | 16px | Default gap between row elements (thumbnail↔name, name↔price block), page horizontal padding on mobile |
| lg | 24px | Section padding on product detail page (price block, trend block, metadata block), page horizontal padding on desktop |
| xl | 32px | Gap between major page regions (search/filter bar ↔ list), detail-page thumbnail size |
| 2xl | 48px | Row min-height (dense list), major section breaks on detail page |
| 3xl | 64px | Page-level top padding, catalog page header height |

Exceptions:
- **List-row thumbnail: 32px** — coincides with the `xl` token; not a true exception, called out for clarity since it's a fixed component size, not a gap.
- **Detail-page thumbnail: 96px** — exceeds `3xl`; a deliberate one-off for the single hero-image use case on the product detail page (multiple of the base-4 unit, `2xl` × 2).
- **Row min-height: 48px, chips and search-clear tap target: 44px min** — chosen to satisfy the ~44px WCAG minimum comfortable touch target on mobile even though rows are otherwise dense; do not shrink below this on any viewport.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 12px | 400 (regular) | 1.5 |
| Heading | 18px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

Only 2 weights exist in this system: **400 regular** and **600 semibold**. Never introduce a third weight (no light/bold-800/black).

**Usage notes (exact mapping — do not improvise):**
- **Label (12/400)** — set badges, `product_type` chip labels, freshness caption ("Data as of…"), `listing_count` caption, muted insufficient-data dash, page micro-copy.
- **Body (14/400)** — list-row product name, item-price + shipping secondary line (always visible per D-05), search input text/placeholder, empty/error state body copy.
- **Heading (18/600)** — list-row `total_price` (the row-level headline per D-05, sized for a compact row, not the full Display size), product detail page's `display_name`, section labels ("Price", "Trend") on the detail page.
- **Display (28/600)** — the product detail page's big `total_price` number only. This is the single largest text on the entire site; never reuse it in the list view (would break row density/D-01).

## Color

**Theme: dark**, in deliberate reference to poe.ninja's actual dense-data aesthetic (CONTEXT.md's explicit inspiration for D-01's layout choice) — not a generic light SaaS template.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B0D12` | Page background |
| Secondary (30%) | `#171A21` (surfaces) / `#232833` (hairline row dividers, inactive chip background) | List rows, detail-page card sections, nav header, inactive filter chips |
| Accent (10%) | `#E8A33D` (warm gold — evokes TCG foil-pack branding) | Reserved **only** for: the active/selected filter chip's background, the search input's focus ring/border, the "Back to catalog" link and any inline text link, and a 2px accent underline beneath the product detail page's `display_name` heading. |
| Destructive | `#D92D20` | Reserved but **unused this phase** — no destructive/write actions exist (read-only SPA, confirmed by RESEARCH.md's Security Domain V4). Kept distinct from trend-down red below so a future destructive action (later milestone) is never visually confused with "price went down." |

Accent reserved for: active filter chip background, search-input focus border, text links (e.g. "Back to catalog"), product-detail heading accent underline. **Never** apply accent to trend badges, thumbnails, or general row hover — those use the semantic trend colors below or a neutral hover state (`#1D212B`).

**Text colors** (not part of the 60/30/10 split, but required for contrast):
- Primary text (on dark surfaces): `#F5F6F8`
- Secondary/muted text: `#9AA3B2`
- Disabled/no-data text: `#6B7280`

**Semantic trend colors (locked by D-06/D-07, extended here to resolve RESEARCH.md's two Open Questions):**

| State | Color | Rendering |
|-------|-------|-----------|
| Up (`status:"ok"`, `pct_change > 0`) | `#34C759` (green) | Filled badge chip, `+X.X%` |
| Down (`status:"ok"`, `pct_change < 0`) | `#FF5C5C` (red) | Filled badge chip, `-X.X%` |
| **Flat (`status:"ok"`, `pct_change === 0`)** | `#8A94A6` (neutral gray) | Filled badge chip, `0.0%` — **resolves RESEARCH.md Open Question 2**: exactly-zero movement gets its own neutral gray, distinct from both up/down and from the insufficient-data dash below. |
| Insufficient data (`status:"insufficient_data"`) | `#5B6472` (dimmer muted gray, text only, no chip fill/background) | `—` with `aria-label="insufficient data"`, per D-07 — visually quieter than the flat state's filled chip, so "zero movement" and "no data" never look identical. |

Note `#FF5C5C` (trend-down) and `#D92D20` (destructive) are intentionally different reds — never reuse trend-down red for error banners or vice versa; an error state uses muted-surface backgrounds with primary/secondary text plus the destructive red only as a small icon/border accent, never a large red block that could read as "price crashed."

**Resolves RESEARCH.md Open Question 1 (`verified` field):** the `verified` boolean is **not rendered anywhere in the UI this phase.** `price_status: "no_data_yet"` (D-11's muted-row treatment) already visually communicates "not fully actionable yet" for the exact same Pitch Black products that carry `verified: false`. Adding a second, unrequested "verified" badge would duplicate that signal without a product decision backing it — explicitly out of scope per RESEARCH.md's own recommendation.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | No standalone button — the entire product row/card is the clickable target. Accessible link name: **"View {display_name} pricing details"** (verb + noun, applied as `aria-label` on the row's wrapping `<Link>`). |
| Empty state heading | "No products found" |
| Empty state body | "Try a different search term, or clear your filters to see the full catalog." (shown when search text + chip filters combine to produce zero matches in the client-side filter) |
| No-data product row/section | "No pricing data yet" (replaces the price block when `price_status: "no_data_yet"`; paired with the row's muted/grayed styling per D-11 — never omit the row, never show a blank/zero price) |
| Error state — catalog load failure | Heading: "Couldn't load the catalog." Body: "Check your connection and try again." + a "Retry" text link that re-triggers the loader. |
| Error state — product not found (API 404 `not_found`) | Heading: "Product not found." Body: "This product may have been removed from the catalog." + "← Back to catalog" link. |
| Error state — product detail load failure (network/500) | Heading: "Something went wrong." Body: "This product's details couldn't be loaded. Try again." + "Retry" link. |
| Destructive confirmation | None — this phase has no destructive/write actions (fully read-only SPA). |
| Search input placeholder | "Search by product name or set…" |
| Freshness caption (detail page) | "Data as of {relative time}" (e.g. "Data as of 2 hours ago") — per D-09, always relative, never an absolute timestamp. |
| Sample-size caption (detail page) | "Based on {listing_count} active listing(s)" when `listing_count` is present; "Sample size unavailable" when `listing_count` is `null`/absent (older documents pre-date the field, per `price_service.py`). |
| Missing MSRP/release date (Pitch Black-style provisional products) | "—" for a numeric field (MSRP), "TBD" for release date — never crash on `null`, never fabricate a value. |

## Layout & Component Notes

*(Additive to the template — captures the phase's locked product decisions in visual terms so the executor has no ambiguity.)*

**Catalog page (`CatalogPage`, route `/`):**
- Header: page title + search input (placeholder above) + filter chip row, in that vertical order.
- Filter chips: one row of `product_type` chips (Booster Pack / Booster Box / Booster Bundle / ETB — D-13) **plus** one row of `set_name` chips (Pitch Black / Chaos Rising / Perfect Order / Ascended Heroes — Claude's Discretion item, exercised here: added for symmetry with D-13, since 4 named sets are a small, stable, high-value filter). Chips are multi-select-free / single-select-per-group toggle buttons (Label-size text, `sm` padding, `44px` min tap height); active = accent background + `#0B0D12` text; inactive = secondary surface + secondary text.
- List: a flat, continuous list (D-02 — no section breaks, no per-set tabs), sorted by the API's existing order (newest set first). Each row, 48px min-height:
  1. Thumbnail, 32px square, `sm` corner radius. Fallback (when `image_url` is `null`, true for ~11/16 products): a flat secondary-surface square bearing a single-letter/glyph placeholder derived from `product_type` (e.g. a simple box outline SVG) — **never** a broken `<img>` icon.
  2. Name + set badge: `display_name` in Body weight/Heading-adjacent emphasis (Body size, 600 weight override for this one spot to read as a title within the row — still counts as the Body *size* token, just semibold), with a small Label-size set-name badge beneath/inline (colored via secondary surface, not accent).
  3. Price block: `total_price` in Heading role (18/600) as the row headline; `item_price` + shipping breakdown directly beneath in Body role, secondary text color — **always visible**, never behind hover/tap (D-05).
  4. Trend badges: `trend_7d` then `trend_30d`, each rendered per the Color section's 4-state table (up/down/flat/insufficient-data), Label size.
  - When `price_status: "no_data_yet"`: row opacity reduced to ~0.55, price block replaced with the "No pricing data yet" copy (still Heading-weight slot, secondary/disabled text color), trend badges render normally (they are independently always-present objects per Pitfall 5 and will typically also show `insufficient_data`). Row remains in its normal sort position and remains clickable (D-11 — muted, never hidden).

**Product detail page (`ProductDetailPage`, route `/products/:productId`):**
- Top: "← Back to catalog" link (accent color, Body size).
- Header: 96px thumbnail (same null-fallback rule as list) + `display_name` in Heading role with a 2px accent underline + `set_name`/`product_type` as Label-size badges beside it.
- Price section: `total_price` in **Display** role (28/600) as the true headline; `item_price` + shipping breakdown in Body role directly beneath (D-05); sample-size caption (Label role) beneath that (D-08 — detail page only).
- Freshness: "Data as of {relative time}" (Label role, secondary text color), positioned near the price block (D-09/D-10 — detail page only).
- Trend section: `trend_7d` and `trend_30d` shown side by side, each labeled "7d" / "30d" (Label role) above its badge, same 4-state color rendering as the list.
- Metadata: MSRP and release date, each with the null-safe "—" / "TBD" fallback (Pitfall 3), Body role.
- No chart, no `price_points` series, no chart placeholder — API returns none this phase (D-11 of 05-CONTEXT.md); do not reserve visual space implying one is coming.
- If the route loader's fetch 404s: render the "product not found" error state (Copywriting Contract) in place of the whole page body, keeping the "← Back to catalog" link.

**Responsive behavior:** Default to a reasonably responsive dense list, not a distinct mobile redesign. On narrow viewports (<480px), the trend-badge pair may wrap to a second line beneath the price block, and the set-name filter chip row may become horizontally scrollable — but thumbnail, name, and `total_price` headline must always remain visible on a single first line of the row. Never drop `item_price` (D-05 forbids hiding it behind interaction) — it may wrap, never disappear.
