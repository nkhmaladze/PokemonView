## Contract note (READ — resolves a source discrepancy)

CONTEXT D-01, RESEARCH, and the UI-SPEC describe a trend badge in each browse row. The already-shipped Phase 5 `GET /products` list response (`catalog_service._product_summary`) intentionally does NOT include `trend_7d`/`trend_30d` — those fields are added only by `get_product_detail` on the `GET /products/:id` response. The phase boundary (06-CONTEXT.md `<domain>`) is explicit: "pure REST client… no new backend endpoints… the SPA renders what the API already guarantees." Therefore:
- PRICE-03 (trend badge, user-observable) is delivered on the product detail page (06-06), where the API serves trends. This is symmetric with the already-locked decisions that keep `listing_count` (D-08) and freshness (D-10) off browse rows.
- `ProductRow` renders `TrendBadge` DEFENSIVELY: it displays trend badges only when `product.trend_7d` / `product.trend_30d` are present on the row object, and omits them gracefully when absent (which is the case for today's list contract). This keeps rows dense today and lights up automatically if the API list response is ever extended — with no backend change and no N+1 detail fetches (both out of phase scope). Do NOT fetch detail per row and do NOT modify Phase 5 code.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API JSON → rendered list | Product strings (display_name, set_name, image_url) interpolated into the DOM |
| user search text → filter | Free-text query used as an in-memory substring match against loaded data |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Tampering / Information Disclosure | ProductRow, CatalogPage | medium | mitigate | display_name/set_name and search text are rendered via JSX text interpolation (auto-escaped); no raw-HTML sink is used. image_url is only ever used as an `<img src>` attribute for a non-null string value, never as HTML (V5) |
| T-06-01b | Tampering | CatalogPage search filter | low | mitigate | Search text is used only as a local `.toLowerCase().includes()` substring match against already-fetched data — never built into a network query string here (D-14 client-side filtering) |
</threat_model>
