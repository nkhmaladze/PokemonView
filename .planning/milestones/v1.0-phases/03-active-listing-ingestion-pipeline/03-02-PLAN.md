<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Ingestion worker process(es) → shared MongoDB | Multiple worker processes/instances may reach the same datastore; the lock collection is the shared source of truth for "a run is in progress" |
| Killed/crashed worker → future scheduled runs | A process that dies mid-run could leave durable state (a held lock) that blocks all future runs |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-02 | Denial of Service | `ingestion_locks` (stale lock) | medium | mitigate | TTL index on `ingestion_locks.expires_at` with `expireAfterSeconds=0` (Task 1) bounds the worst case: even a hard-killed worker that never runs its `finally` release_lock self-heals once its stored `expires_at` passes, so a stale lock cannot block runs indefinitely |
| T-03-04 | Tampering / resource exhaustion | eBay daily rate-limit budget (shared across worker instances) | medium | mitigate | Providing the `ingestion_locks` collection is the storage precondition for the cross-process lock (Plan 03-04) that makes a second concurrent worker instance skip its run and issue zero eBay calls, protecting the shared 5,000-calls/day budget |
| T-03-06 | Tampering | `price_points` schema contract | medium | mitigate | Introducing a separate `active_listings` collection (not writing into `price_points`) preserves Phase 2's creation-time-only time-series schema; the docstring correction (Task 2) prevents a future executor from mistakenly writing unmatched raw listings into `price_points` |
| T-03-CFG | Information Disclosure | `init_collections(db)` | low | accept | The function receives an already-connected db handle and never reads MONGODB_URI or constructs a MongoClient — no credential surface is added here |
