<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| eBay Browse API response → worker | eBay responses are external/untrusted input; field shapes (price, shippingOptions, itemId) may be missing or malformed |
| Worker process → logs/stderr | Access token and MongoDB URI must never cross into log output |
| Multiple worker processes/instances → shared MongoDB + shared eBay rate budget | Overlapping runs could double-count API usage and race on writes |
| Killed worker → future runs | A crash before `finally` could leave the lock held |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Information Disclosure | worker logging (get_app_token / MONGODB_URI) | medium | mitigate | Log only counts, per-product query strings, and token metadata — never the raw access token, Authorization header, or connection string (reuses ebay_client's discipline); main() reads MONGODB_URI via os.environ, never prints it |
| T-03-02 | Denial of Service | stale lock (crashed worker) | medium | mitigate | run_ingestion_once wraps the run in try/finally with release_lock in finally; the ingestion_locks TTL index (Plan 03-02) is the last-resort self-heal if the process is hard-killed before finally executes |
| T-03-03 | Denial of Service | malformed eBay item (missing/typed price or shipping) | medium | mitigate | upsert_listings skips items without a `price` key and wraps each item's doc-build in try/except so one malformed item never aborts the batch; per-product try/except in run_ingestion_once isolates a failing product into errors[] without aborting the run |
| T-03-04 | Tampering / resource exhaustion | shared eBay 5,000-calls/day budget across concurrent instances | medium | mitigate | acquire_lock over ingestion_locks makes a second concurrent worker instance take the skipped_locked path and issue ZERO eBay calls that run, protecting both data integrity and the shared rate budget (SC-2) |
| T-03-05 | Tampering | idempotency of listing writes | low | mitigate | upsert_listings uses bulk_write([UpdateOne(_id=itemId, upsert=True)]), never insert_many, so overlapping/retried runs cannot create duplicate listing documents (INGEST-02) |
</threat_model>
