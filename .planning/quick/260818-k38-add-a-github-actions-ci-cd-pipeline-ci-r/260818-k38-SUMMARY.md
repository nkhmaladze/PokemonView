### Task 4: Add FLY_API_TOKEN secret and confirm the first main-branch deploy

**What was built:** A single workflow, `.github/workflows/ci.yml`, with three jobs: `backend` (full 73-test pytest suite against an ephemeral MongoDB 7 service container), `frontend` (oxlint, vitest, vite build), and `deploy` (backend-only `flyctl deploy --remote-only` to Fly app `pokemonview`, gated on push-to-main, on both CI jobs passing, and on the FLY_API_TOKEN secret existing). CI has been verified green on a real pull request (#1), and the deploy job has been verified not to run on pull requests.

**How to verify — two things need the repo owner, because neither can be done from this session:**

1. **Create the deploy token secret** (the one manual step; no agent will read, write, or echo this value):
   a. Generate a scoped Fly deploy token locally: `fly tokens create deploy -a pokemonview` and copy the full output, including the `FlyV1 ` prefix.
   b. Go to GitHub → `nkhmaladze/PokemonView` → Settings → Secrets and variables → Actions → New repository secret.
   c. Name it exactly `FLY_API_TOKEN` (any other name and the deploy step will silently self-bypass). Paste the token as the value and save.
   Prefer a scoped deploy token over a personal access token — it can only deploy this one app, so a compromised runner cannot reach the rest of your Fly account.

2. **Merge the pull request and confirm the deploy.**
   a. Review and merge PR `ci/github-actions-pipeline` (https://github.com/nkhmaladze/PokemonView/pull/1) into main.
   b. Watch the resulting main-branch run: `gh run watch --exit-status` (or the Actions tab). Expect `backend` and `frontend` to pass, then `deploy` to run and succeed.
   c. Confirm the app is live and serving after the deploy: check `fly status -a pokemonview` and load the API.

If you merge **before** adding the secret, that is safe and expected: `backend` and `frontend` still run, and `deploy` prints its "secret not configured" notice and passes rather than failing. Add the secret afterwards and the next push to main will deploy.

**Resume signal:** Type "approved" once the secret is added and the main-branch deploy has succeeded, or describe what failed.
